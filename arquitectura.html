TOPOLOGIA DEL ECOSISTEMA
Hydra se organiza bajo un patrón de microservicios independientes. Cada servicio Spring Boot se despliega por separado y comparte una única base de datos PostgreSQL administrada en Supabase.

Los clientes (APK, escritorio y web) consumen las APIs por HTTPS. El servicio hydra_realtime mantiene canales SSE para empujar eventos clínicos sin sondeo periódico.

DISEÑO POR CAPAS
Internamente, cada microservicio opera mediante una arquitectura de capas estricta para asegurar la separación de responsabilidades.
1. CONTROLLER LAYER
Expone los endpoints REST, recibe los DTO y delega la orden al Service.
2. SERVICE LAYER
Contiene la lógica de negocio: validaciones, reglas clínicas, cifrado y comunicación entre servicios.
3. REPOSITORY LAYER
Interactúa con PostgreSQL mediante Spring Data JPA y PostgREST.
DATABASE (POSTGRESQL / SUPABASE)
COMUNICACION Y TIEMPO REAL
Los servicios se comunican por REST sobre HTTPS y comparten el modelo de datos en PostgreSQL. Para el monitoreo clínico, hydra_realtime publica eventos mediante Server-Sent Events (SSE), reemplazando el sondeo periódico y reduciendo la latencia y la carga sobre la base de datos.
// Hydra Realtime - canal SSE de eventos clinicos @GetMapping(value = "/api/eventos/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE) public SseEmitter streamEventos() { SseEmitter emitter = new SseEmitter(0L); eventService.registrar(emitter); return emitter; }
ENDPOINTS CRITICOS
Cada microservicio expone su propio puerto. REGLA DE ORO: los clientes nunca acceden directamente a la base de datos; toda operación pasa por una API autenticada.
GET http://localhost:8080/api/pacientes
Lista los pacientes registrados (hydra_crud). Requiere token JWT.
POST http://localhost:8081/api/auth/login
Autentica al usuario y emite el token JWT firmado con RSA256 (hydra_arm_security).
{ "rut": "12.345.678-9", "password": "********" }
GET http://localhost:8082/api/ubicacion/{idPaciente}
Obtiene la última ubicación conocida del paciente (geolocalización).
GET http://localhost:8083/api/eventos/stream
Canal SSE con BPM, SpO2, batería y alertas en tiempo real (hydra_realtime).
SETUP TACTICO DE PRUEBAS
Para ejecutar pruebas eficientes en Postman durante la presentación:
  1. Crea una Colección llamada "Hydra — Proyecto APT".
  2. Configura variables de entorno: {{crud}} = http://localhost:8080, {{security}} = http://localhost:8081, {{geo}} = http://localhost:8082, {{realtime}} = http://localhost:8083.
  3. Usa la variable en todas tus rutas: {{crud}}/api/pacientes. Si un servicio cambia de puerto, solo cambias la variable.
  4. Envía el Body en formato raw -> JSON y adjunta el token JWT en el header Authorization.

Flujo de una emergencia:
  • El sensor detecta una anomalía en las constantes vitales.
  • El ESP32 transmite el dato a la API y se persiste en Supabase.
  • Hydra Realtime emite el evento por SSE a las tres interfaces.
  • El cuidador recibe la alerta y puede despachar una ambulancia desde el chat.
DESPLIEGUE E INFRAESTRUCTURA
Nube: Render para los microservicios y Cloudflare para la publicación del frontend. Datos: PostgreSQL administrado en Supabase y Supabase Storage (S3) para archivos. Hardware: ESP32 conectado por WiFi/BLE a la red del paciente. Seguridad: HTTPS/TLS en todas las comunicaciones y secretos en variables de entorno.

Herramientas: VS Code, Android Studio, Postman, Supabase Studio, GitHub y navegador web.
